Latest changes

01What changed in 3.10.4

Manual Chroma is optional and off by default: automatic selection uses compatible 4:2:0. A matched backend enables validated NVIDIA encoding on supported wlroots Wayland sessions. Version 3.10.4 also fixes Python interpreter alias recognition and removes the legacy helper's dependency on mapfile. English, Best · Auto · 23 FPS · 4K remain the first-run defaults.

OPTIONAL CHROMA

Automatic first, manual when needed

Leave Manual Chroma unchecked for automatic compatibility. Enable it to choose 420 or CPU-only 444. Disabling the control resets manual selection to auto; it does not remove chroma subsampling from the video format.

PROFILE STARTUP

More than an encoder listing

A bounded synthetic full hardware-profile check runs in a GUI worker and caches profile results. This validates startup, not physical screen/audio/camera capture or every GPU and operating system.

EXPLICIT GPU

Hardware requests stay honest

GPU choices are enabled only after the selected backend passes a synthetic profile check. A matched wf-recorder/FFmpeg pair supports NVENC; explicit GPU failures never masquerade as CPU success. Auto may fall back to a usable software encoder.

RECOVERY

No false Saved outcome

The GUI preserves intermediate recordings if final muxing fails. The legacy Wayland launcher now also reports failed or empty recordings correctly instead of printing Saved. Recovery files can contain private screen and audio content.

ZUPT DISTRIBUTIONS

Real archives, native packages retained

Portable Unix, Guix and complete source retain genuine .zupt archives, each holding one uncompressed tar payload for Unix modes and symlinks. Ten payloads plus SHA256SUMS make 11 release assets; these are not .tar.gz downloads.

DEFAULTS

Familiar defaults and platform safeguards

Best, Auto, a literal 23 FPS and 4K remain the defaults, with manual Chroma disabled. Existing BSD capability checks and Windows Unicode DirectShow IDs, native window handles and signed multi-monitor handling remain in place.

Core capabilities

02One focused recorder, every capture path

Turbo Recorder is a quality-first orchestration layer over FFmpeg, wf-recorder, platform capture APIs and the hardware encoders already present on the machine.

ZERO CONFIG

Safe automatic capture

Detects OS, display server, GPU, encoder, screen, microphone and loopback source, then chooses the richest mode that can actually run.

HW ACCEL

Profile-checked GPU startup

Hardware candidates receive synthetic startup checks before selection. Auto prefers hardware AV1, HEVC and H.264 in that order, then software H.264 through libx264 or a runtime-verified libopenh264. Physical capture still depends on the platform and devices.

OBS STYLE

Screen, monitor, window, region

Capture the full desktop, a physical monitor, a native window target or a precise signed region using the active platform backend.

WAYLAND + X11

Platform-aware screen paths

Linux uses wf-recorder on wlroots sessions and x11grab on X11; BSD uses its supported x11grab path on X11 or through XWayland.

4K DEFAULT

Standard output resolutions

4K is selected initially; native, 720p, 1080p and 1440p remain available. Lanczos scaling preserves aspect ratio and pads to the exact standard frame.

WEBCAM

Picture-in-picture overlay

Select a camera, size and corner. BSD cameras appear only when FFmpeg provides V4L2 and a real capturable device node exists.

DENOISE

Clean the microphone only

Light, medium or strong FFmpeg-based noise suppression plus high-pass filtering, without touching clean system audio.

GO LIVE

YouTube and custom RTMP(S)

H.264, AAC, a two-second keyframe interval and FLV are selected for streaming. The GUI masks the key and output text redacts it.

AUDIO

FLAC, mixing and channel repair

Lossless FLAC is the file default, with AAC and Opus alternatives. Clone left/right, average to mono or preserve stereo.

ADAPTIVE Q

Quality follows pixel throughput

Slow, quality-heavy presets are used when there is headroom; 4K and high frame rates step toward faster real-time settings.

GUI + CLI

Interactive and scriptable

A focused Tk interface and a complete command line share the same detection and pipeline builder. Python uses the standard library only.

PACKAGED

Install where you work

Debian, RPM, AppImage, FreeBSD and Windows EXE/installer retain native formats. Guix, portable Unix and complete source are distributed as .zupt archives.

Pipeline

05From probe to finalized output

The same four-stage plan powers the GUI and command line, keeping platform-specific discovery separate from the final FFmpeg or wf-recorder execution.

Probe the machine

Resolve the operating system, display server, CPU/GPU, screens, native targets, microphones, loopback sources, cameras and FFmpeg encoders.

Validate the backend

Try hardware encoders in priority order, then validate the selected synthetic recording profile with cached startup checks. Auto skips unusable candidates; explicit GPU failures are reported.

Build the graph

Add scaling, webcam overlay, mic denoise, channel mapping and mic/system mixing, then select file encoding or a streaming-safe H.264/AAC plan.

Run and finalize

Force constant frame rate, preserve BT.709 metadata, display elapsed time and size, and stop cleanly with q, Ctrl-C or a duration.

Wayland scope. Native Wayland capture targets Linux wlroots compositors. GNOME and KDE may require X11/Xorg; BSD sessions use X11/XWayland. NVIDIA encoding requires a matched wf-recorder/FFmpeg backend and working driver. GPU encoding still uses CPU-side capture/conversion; it is not zero-copy. Generic wf-recorder cannot be assumed to share the encoders of an unrelated FFmpeg binary. Intel/AMD VAAPI remains conditional on backend and device support.

Camera, audio and streaming

07Produce a complete recording in one pass

Camera composition, clean voice, desktop sound and live delivery are part of the same pipeline instead of separate post-processing steps.

webcam--camera accepts V4L2 devices, AVFoundation indices or DirectShow names; size can be small/medium/large, explicit WxH or a percentage.
positionTop-left, top-right, bottom-left, bottom-right or center. The camera is composited before the final encoder stage.
denoiseoff / light / medium / strong through adaptive FFmpeg afftdn, with high-pass filtering at medium/strong levels.
channelsleft or right clones one live channel to both outputs; mono performs a clip-safe average.
streamYouTube by default or any explicit RTMP/RTMPS ingest. File-only video streams receive a silent track so the platform still sees audio.
camera + denoise + stream
# inspect available cameras
$ turborec cameras

# screen + voice + system audio + picture-in-picture
$ turborec record -m video_both \
    --camera /dev/video0 \
    --camera-size medium \
    --camera-position bottom-right \
    --denoise medium

# send the same production to YouTube
$ turborec record --stream YOUR_KEY \
    --camera /dev/video0 --denoise medium

# custom ingest
$ turborec record --stream KEY \
    --stream-url rtmps://host/app

Credential note. Stream keys are replaced with bullets in command previews, dry runs and status output. A key supplied on the command line can still appear in shell history and in the local process list while live; the masked GUI field is the safer choice on shared systems.

Output and encoder tuning

08Quality that scales with the workload

The quality level and output pixel throughput determine the encoder speed tier. These presets target live capture, but cannot guarantee real-time performance on every machine; reduce resolution/FPS when the encoder cannot keep up.

besthighbalancedcompact native720p1080p1440p4K
pixel tiersUp to roughly 65, 130 and 260 megapixels/second, then the high-throughput tier above 260 MP/s.
NVENCQuality VBR with spatial AQ; P7/P6/P5 presets selected by throughput, with temporal AQ and look-ahead when there is headroom.
softwarex264 scales from slow to veryfast, x265 from medium to veryfast, and SVT-AV1 from preset 6 toward 11 as throughput rises.
resolutionLanczos fits the capture with even dimensions and square pixels, then pads to the exact target frame. Native odd dimensions are padded right/bottom without cutting pixels. Upscaling adds no captured detail.
chromaAuto is the default, with Manual Chroma off; it selects compatible 4:2:0. Manual 444 requires CPU libx264 (Auto/H.264, High 4:4:4) or libx265 (HEVC, Main 4:4:4 8-bit), using yuv444p. AV1, RTMP(S), missing software encoders and explicit GPU requests fail. Not lossless RGB.
fidelityConstant-frame-rate output, BT.709 metadata and software Wayland conversion, lossless FLAC by default and high-quality soxr resampling.
quality recipes
# native size, safe automatic sources, best quality
$ turborec record -R native

# true 4K frame, HEVC, 23 fps
$ turborec record -R 4k -c hevc -f 23

# 1440p H.264 with explicit GPU preference
$ turborec record -R 1440p -c h264 --gpu

# CPU H.264 file with full chroma resolution
$ turborec record -R native --chroma 444 -c h264

# lossless audio-only mix
$ turborec record -m audio_both \
    --audio-codec flac

# repair a mic wired to the right input
$ turborec record -m video_mic \
    --audio-channels right

Packages install both turborec and the Linux Bash front-end turborecorder, plus the desktop launcher and icon where the package format supports them.

# Fedora / RHEL
$ sudo dnf install ./turborec-3.10.4-1.noarch.rpm

# portable AppImage

# GNU Guix from the repository
$ guix package -f guix.scm

# SecurityOPS Channel, after configuring it and guix pull
$ guix install turborec

# Replace an installed generic package; compatible NVIDIA driver required
$ guix package -r turborec -i turborec-nvidia-new-feature

# Guix pack: verify SHA256SUMS BEFORE extraction to /
$ zupt extract -o guix-unpack turborec-3.10.4-guix-x86_64.zupt
$ sudo tar xf guix-unpack/turborec-3.10.4-guix-x86_64.tar -C /

# FreeBSD package
$ pkg add ./turborec-3.10.4.pkg
$ pkg install python3 ffmpeg

# macOS / BSD / Unix archive, user-local prefix
$ zupt extract -o unpack turborec-3.10.4.zupt
$ tar xf unpack/turborec-3.10.4.tar
$ cd turborec-3.10.4

RUNTIME

Dependencies outside the Windows executable

Python 3.8+, FFmpeg and Tk for the GUI. Linux Pulse/PipeWire discovery uses pactl. BSD microphones use a real sndio/OSS device when supported; pactl is optional and needed for Pulse monitor/system audio. Linux wlroots Wayland also needs wf-recorder and either swaymsg or wlr-randr. Fedora ffmpeg-free can use a proven libopenh264 fallback if libx264 is absent. The CLI works without Tk.

macOS permissions. Grant Screen Recording, Microphone and Camera access to Terminal, Python or the launcher that starts Turbo Recorder, then fully restart that application.

Command line

10Inspect, automate and record

Inspection commands can return JSON for diagnostics and scripts. The record command accepts the same sources, quality, camera, audio and streaming controls as the GUI.

inspect and record
# machine and target discovery
$ turborec detect
$ turborec devices
$ turborec cameras
$ turborec targets
$ turborec encoders

# JSON diagnostics
$ turborec detect --json
$ turborec devices --json
$ turborec cameras --json
$ turborec targets --json

# preview without creating output or stream pipes
$ turborec record --dry-run
targeted capture
# strict screen + mic
$ turborec record -m video_mic -q high -f 30

# monitor, native window or exact signed region
$ turborec record --monitor HDMI-1
$ turborec record --window "My Browser"
$ turborec record --region 1280x720+100+50

# fixed duration, countdown, open when complete
$ turborec record -t 5m --countdown 3 --open

# force the backend
$ turborec record --gpu
$ turborec record --cpu

Modes. auto (default), video_both, video_mic, video_system, video_only, audio_both, audio_mic and audio_system. Save defaults with --config, $TURBOREC_CONFIG or ~/.config/turborec/config.json. Stop with q or Ctrl-C.

Linux Bash front-end

11The dependency-light path

turborecorder is the lighter Linux-only interface. It auto-detects X11 or wlroots Wayland, selects x11grab or wf-recorder and supports screen with system audio, microphone, or a synchronized mic+system mix.

install
$ chmod +x turborecorder
$ sudo mv turborecorder /usr/local/bin/
usage
$ turborecorder
$ turborecorder -m video_both -Q best
$ turborecorder -m video_mic -C hevc -f 30
$ turborecorder -S
$ turborecorder -h

Wayland finalization. Both front-ends pass wf-recorder's no-damage/constant-frame-rate option so a static desktop still polls the stop condition and finalizes cleanly. A temporary PipeWire combined source is created for synchronized mic + system capture and removed afterward.

Security and privacy

12Small surface, explicit boundaries

The application and this website avoid hidden network behavior, minimize dependencies and keep potentially sensitive targets and credentials visible to the operator.

THIS PAGE

No JavaScript or third-party requests

CSS is inline; the screenshot and favicon are same-origin. The CSP blocks scripts, connections, frames, objects, media and third-party images or fonts. External URLs activate only after a user follows a link.

CREDENTIALS

Stream keys are redacted

Keys are masked in GUI fields, previews, dry runs, child-process output and end-of-stream status. The process-list caveat is stated rather than hidden.

CAPTURE SCOPE

Regions fail closed

Malformed or zero-size regions are rejected. Stable device IDs, window handles and display identifiers remain attached behind human-readable labels.

BUNDLED EXE

Private executable search path

The frozen Windows build exposes only the private bundle directory containing its FFmpeg, not the Downloads folder or another untrusted launch directory.

ENCODERS

Matched Guix backend

The SecurityOPS Channel keeps a free CPU package and an optional NVIDIA variant. The latter pins wf-recorder to FFmpeg 8.1.3 for ABI compatibility, while FFmpeg 9.0.2 handles other processing. It does not install a kernel driver or reboot. Consult the guide before replacing packages or configuring an external backend.

SUPPLY CHAIN

Checksummed release gate

Release CI validates platform artifacts, creates SHA-256 sums and verifies publication before the version is considered complete.
